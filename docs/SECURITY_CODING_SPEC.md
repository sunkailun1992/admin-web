# 前端安全编码规范

本文件只维护 `admin-web` 前端安全规则。AI 新增或修改页面、按钮、请求服务、登录态、上传下载、富文本、脱敏、批量操作时，必须先阅读本文件。

## 权限边界

- 前端权限只负责菜单和按钮展示，不代表接口安全；新增页面或按钮时必须确认后端接口已有 `@PreAuthorize` 和权限资源。
- 修改、删除、授权、导入、导出、批量操作必须有二次确认、失败提示和权限判断，不允许只靠隐藏按钮防护。
- 前端不得构造或伪造角色、权限、租户和用户归属；这些安全事实必须以后端返回和当前登录态为准。

## 请求和登录态

- 请求服务必须集中在 `src/services`，不得在页面里临时拼接 token、租户、用户或 URL 绕过统一拦截器。
- 登录退出、401、403 和切换账号时必须清理本地 token、登录信息和租户选择，避免旧 token 或旧租户上下文残留。
- 不要把 token、密码、验证码、密钥、身份证、完整手机号、完整邮箱等敏感信息写入 URL、路由参数、控制台日志或页面状态快照。

## 脱敏展示

- 表格、详情、导出和日志页面展示个人信息时必须按后端 VO 或前端工具做脱敏，不展示超出当前页面业务需要的字段。
- 错误提示只展示用户可理解的业务信息，不展示接口堆栈、内部地址、请求头、token 或后端异常详情。
- 调试日志不得提交到正式代码；确需保留日志时只能输出非敏感元数据。

## XSS 和输入安全

- 页面只渲染普通文本；不得直接使用 `dangerouslySetInnerHTML`。
- 确需渲染富文本时，必须使用白名单清洗并说明数据来源可信边界。
- 用户输入只能作为接口参数提交，不得拼接到选择器、HTML、脚本、URL 跳转目标或下载路径中，防止 XSS、开放重定向和路径遍历。
- 查询条件、排序字段和显示字段必须来自后端允许字段或前端白名单，不把用户输入直接传成任意 SQL 字段语义。

## 文件上传下载

- 文件上传控件必须限制大小、数量、扩展名和 MIME 类型；上传前后都要依赖后端二次校验，前端校验不能视为安全边界。
- 文件下载不得直接信任后端返回或用户输入的文件名；展示文件名要转义，保存文件名要去除路径分隔符。
- 导入页面必须展示失败原因并避免回显敏感原始内容，防止把用户文件内容直接渲染为 HTML。

## 验收要求

- 新增页面测试或手工验收必须覆盖未登录、登录过期、无权限、切换租户后数据隔离和接口失败提示。
- 高风险操作必须验证二次确认、取消操作、失败提示、权限不足和成功刷新。
- 上传下载必须验证非法格式、超限文件、空文件、危险文件名和接口失败提示。
