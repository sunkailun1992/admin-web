# 前端测试分层规范

本文档约束 `admin-web` 的前端测试策略。前端测试默认与真实后端隔离，只有明确标记为真实网关一组或联调验证时，才允许请求 test 环境真实网关。

## 核心原则

- 测试目标是验证用户可见行为、请求契约、权限展示和安全边界，不测试 React、Radix、TanStack 或浏览器本身。
- 普通 CI 默认不访问真实后端接口，不读取 `.env.prod`，不使用生产 token，不改生产数据。
- 构建通过只能证明项目可构建，不能替代表单、权限、请求头、异常提示和页面交互测试。
- 普通 CI 用 `pnpm build:dev` 选择开发构建配置，生产构建入口仍为 `pnpm build`。
- 前端权限、按钮隐藏和菜单控制只是体验层保护，不能替代后端鉴权、租户隔离和数据权限。
- 修改测试时必须说明覆盖的真实业务风险，不能只断言模拟返回值。

## 测试分层

| 层级 | 目标 | 工具 | 是否访问真实接口 |
| --- | --- | --- | --- |
| 静态门禁 | 格式、代码检查（含子应用引用边界与界面文案规则）、类型、构建 | Prettier、ESLint、TypeScript、Vite | 否 |
| 单元测试 | 权限判断、映射、参数转换、模型与控制器、请求客户端 | Vitest（jsdom 或 Node） | 否 |
| 页面测试 | 列表、表单、弹层、按钮权限、错误提示、请求参数 | Vitest 浏览器模式（Playwright 驱动 Chromium）+ Testing Library + MSW（Service Worker） | 否 |
| 物料测试 | 业务组件行为；每个 Storybook 故事的交互与无障碍检查 | Vitest 浏览器模式、Storybook Vitest 插件 | 否 |
| 浏览器测试（固定数据） | 主应用与四个子应用一起：每个菜单页与它的弹层打开时控制台干净、没有漏拦截的接口；深链接、账户菜单、登录失败页、语言与主题、切换租户、权限、子应用不可用、图谱 | Playwright（`e2e/mock`，接口按 `e2e/fixtures` 回） | 否 |
| 仓库脚本测试 | 工作区约定：开发服务与 Storybook 先构建依赖的包（新克隆后主题样式才解析得到）等 | Node 内置测试运行器（`scripts/test/`，`pnpm test:repo`） | 否 |
| 独立部署验证 | 只重建一个子应用（改它的一条文案与版本号），主应用不变也用上新版 | `pnpm test:deploy` | 否 |
| 浏览器测试（真实网关） | 登录、每个菜单页无错误警告与 5xx、部门新建后删除、登录失败页、退出后会话失效 | Playwright（`e2e/live`） | 只允许 test 环境 |

## 当前门禁

- **单元与页面**：各应用的 Vitest 配置分两个项目：`unit` 在 jsdom 里跑（MSW 在 Node 里拦截），`pages` 在真实浏览器里跑（MSW 的 Service Worker 拦截，脚本由 `msw/vite` 的 worker-only 模式提供）。本机用系统装的 Chrome，CI 用 Playwright 自带的 Chromium。`packages/ui` 另有 `components` 与 `storybook` 两个浏览器项目。
- **共用时限**：`@admin-web/config-vitest` 统一 Vitest 单个用例上限（15 秒）与 Testing Library `findBy*`、`waitFor` 的等待上限（5 秒）；各包测试配置与 setup 文件都引用它。CI 机器比本机慢几倍，1 秒的默认等待会误报；条件一满足就返回，通过的用例不会变慢。
- **固定数据一组**（`pnpm test:e2e`）：`build:dev` 后起五个预览服务（主应用 8001，子应用 8201–8204），`page.route` 拦截全部接口，返回 `e2e/fixtures/` 的合成数据；没有固定数据的接口回 501 并让用例失败；子应用清单改指预览端口。进 CI，失败时保留 trace、截图与 HTML 报告（`e2e-out/`）。
- **真实网关一组**（`pnpm test:e2e:test`）：`build:test` 后预览，主应用在 8000 端口（已在 Keycloak 登记回调，被占用时直接报错，不复用别的服务），经真实网关与 Keycloak 登录一次后串行跑。只经维护者本机的全链路脚本 `run_chain_verify.py --admin-web-e2e` 运行，账号口令由脚本放进 `ADMIN_WEB_E2E_USERNAME`、`ADMIN_WEB_E2E_PASSWORD`，不写进仓库与命令行；不留 trace 与截图。
- **类型**：`e2e/` 与 `playwright.config.ts` 由根任务 `typecheck:repo` 检查（Playwright 运行器本身不做类型检查）。
- **仓库脚本测试**：根任务 `test:repo` 用 Node 内置测试运行器跑 `scripts/test/*.test.mjs`，按 Turborepo 的任务图（`--dry=json`）核对开发服务与 Storybook 都先构建主题包；`pnpm test` 与 `pnpm check` 都含它。

任何功能改动至少执行：

```bash
pnpm check
pnpm test:e2e
bash scripts/check-secrets.sh
```

`pnpm check` 跑格式、lint（警告也算失败）、各包与 e2e 的类型检查、全部单元与页面测试、`build:dev`。CI 另跑固定数据一组、生成器检查、独立部署验证与密钥扫描。提交时 husky 的 pre-commit 钩子对暂存文件跑 `eslint --fix` 与 `prettier --write`。

修改登录、路由、权限、请求拦截、环境变量、网关地址或核心管理页面时，还必须本地打开页面验证，并说明验证的页面、账号环境、请求路径和失败场景；合并前再跑真实网关一组。改子应用接入、共享单例或构建配置时跑 `pnpm test:deploy`。

## 单元测试规则

- 各子应用 `src/access.ts` 的权限规则必须覆盖有权限、无权限、未登录、资源为空与管理员分类（照 1.2.4 逐条对照，见各子应用的 `test/unit/access.test.ts`）。
- 参数转换函数必须覆盖空值、分页、排序、搜索条件、`tenantId` 和 `version`。
- 枚举、状态、标签、颜色、文案映射必须覆盖未知值兜底。
- 子应用的 `./routes` 要测路由与菜单（路径、文案键、权限规则、分组）与自带的文案；单独运行外壳要有冒烟测试。
- 不为 Radix、TanStack 等第三方库的内部行为写测试；只验证本项目自己的业务逻辑。

## 页面测试规则

- 以用户行为为中心，按角色、可访问名称、label、按钮名称查找元素；不直接断言组件内部 state、私有方法或脆弱的 DOM 结构。
- 租户、部门、用户、角色、权限资源页面至少覆盖列表渲染、新建弹窗、编辑回显、表单校验和提交。
- 权限相关组件必须覆盖有权限显示、无权限隐藏或禁用、接口失败提示。
- 表单提交测试必须验证最终发出的请求，特别是 `tenantId`、`id`、`version`、分页参数和业务编码。
- 用例要等到界面终态再结束：写操作后等弹窗关闭或重新读取完成（如 system 的 `closed()`、ai 的 `settled()`），开始操作前等按钮可用；不要在写请求一到处理器就结束，否则随后的读取会落进下一个用例。

## Service/API 测试规则

- 用户中心 `/auth/**` 直接请求同路径网关，不额外追加 `/user`；RAG 文档、检索和图谱接口用 `/api/rag/**`，不得重复追加 `/rag`。请求契约测试直接执行真实 service，只用 MSW 替换网络。
- `@admin-web/api` 的客户端测试必须验证会话请求头（不带 `Authorization`；`X-Requested-With`、写请求的 `X-XSRF-TOKEN`、`X-Tenant-Id`）与 `X-Release-Version`、`X-Traffic-Lane` 等灰度头的传递规则，以及 401、业务失败、HTTP 错误的处理。
- 列表查询必须验证分页、搜索、排序字段和字段白名单参数。
- 新增和编辑请求必须验证请求体不携带前端临时字段；编辑请求必须携带后端乐观锁 `version`。
- MSW 对没有处理器的请求报错（`onUnhandledFrame: 'error'`）；不打真实 `localhost:7100`、test 或 prod 网关。

## 浏览器测试规则

- 真实网关一组只允许连接 test 环境网关，禁止连接 prod。
- 真实网关一组使用测试租户、测试账号和可清理的测试数据；新增数据必须带稳定测试前缀（合成部门叫 `e2e-<时间戳>`，失败也在 `afterAll` 里经接口删掉）。
- 两组都要求每个页面打开后控制台没有错误和警告、没有页面错误；真实网关一组另要求没有 5xx，并记下统一错误体里的错误码（区分 C0001、C0110 等）。不设控制台允许清单：本项目代码打出的错误与警告一律改掉，第三方库的问题先查清楚再处理。
- 固定数据一组的用例经 `e2e/support/setup.ts` 的 `prepare()` 准备，结束时 `verify()` 核对没有漏拦截的接口与控制台问题。
- 失败时要留下能定位的证据：固定数据一组保留 trace、失败截图与 HTML 报告；真实网关一组只出终端输出（控制台消息、5xx 与错误码、卡住的动作），不写 trace、截图与报告，以免把登录输入和真实数据写到磁盘。
- 生产发布前如未执行真实网关一组，交付说明必须明确未执行原因和剩余风险。

## 测试稳定性

- 测试结果只能由输入决定，不依赖真实时间、定时器、网络、执行顺序或本机遗留状态。需要时间的逻辑用 Vitest 的模拟计时器；等待异步结果用有总时限的条件等待（`findBy*`、`waitFor`、`expect.poll`），不用固定延时赌时序。
- 每个用例自行准备并清理全局状态（`localStorage`、`sessionStorage`、`history`、MSW 临时处理器）；setup 文件里统一清理。
- 新增或修改涉及请求、定时器或并发的测试，合并前至少做一种放大检查：每个用例单独跑一次；或在共享请求客户端临时给每个请求加几百毫秒延迟后跑全套，确认不依赖响应快慢（探针不进仓库）。
- 偶发失败按缺陷处理：先查明原因再修，不用自动重试、放宽断言、跳过或删除测试换取通过（浏览器测试 `retries: 0`），也不关掉 user-event 的 pointer-events 检查。确需临时跳过时写明原因与恢复条件，并在交付说明中列出。
- 本机 macOS 通过不代表 CI 的 Linux 通过；只在一个平台验证过的结论要写明平台。

## 禁止事项

- 禁止自动化测试读取 `.env.prod` 或生产账号。
- 禁止在单元、页面、物料测试中请求真实后端。
- 禁止为了测试通过关闭权限、关闭请求拦截、跳过会话头、删除租户 header 或硬编码管理员身份。
- 禁止把真实 token、账号密码、手机号、邮箱、身份证、内网地址写入测试代码。
- 禁止只用快照测试覆盖核心业务页面；快照只能作为低价值辅助。
